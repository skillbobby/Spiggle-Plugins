Why teams choose Dynamic Fields

Ship extensible models without redeploying for every new attribute. Operators stay productive; developers keep a typed, queryable store.

01

Rich field catalog

Text, email, phone, URL, number, textarea + editor, select, radio, multi-select, tags, date/datetime, boolean, toggle, and Spatie-backed files.

02

Filament-native admin

Create, clone, and manage definitions in the panel. Options, validation meta, and file settings appear where operators expect them.

03

Drop-in model traits

HasCustomFields + optional HasCustomFieldMedia wire any Eloquent model. Mapper helpers build form, table, and infolist components.

04

EAV done carefully

Definitions, options, and values are normalized tables — not a dumping-ground JSON column. Events and caching keep reads snappy.

05

Files that scale

File fields use Spatie Media Library collections, disks (including S3), MIME limits, image editor, conversions, and reorderable previews.

06

Ops tooling built in

Seed standard user fields, export/import definitions, verify setup, and gate access with Shield-compatible permission names.

From zero to custom attributes

Three steps between a fresh install and fields live on your resources.

1

Install & register

Require the package, publish config, migrate, and register DynamicFieldsPlugin on your Filament panel.

2

Trait your model

Add HasCustomFields (and media traits for files). Map components with CustomFieldMapper in your resource schema.

3

Define in the panel

Operators create fields under System → Custom Fields. No migration. No redeploy. Values save with the host record.
